Guest workflow guide

Give guests your OBS program and live chat

Your guests can join a VDO.Ninja room, see the OBS program, hear its audio, and read Social Stream Ninja chat in the same browser window.

Development status: the Share a link WHEP controls and plugin WHEP hosting described below require the updated frontend, plugin, and WHEP broker. They are development changes until those versions are released and deployed.

1. Start with ordinary room publishing

If OBS is also streaming to YouTube or another destination, use the separate Guest Return tab instead of changing your main streaming service. Set the same room and password, exclude all guest microphones from the return audio track, and use Copy room guest invite. See the group return guide.

  1. Create a VDO.Ninja room as its director. Send each guest their invite link. Bring their feeds into OBS using the plugin's receiving sources or OBS Browser Sources.
  2. In OBS, select the VDO.Ninja streaming service. In Tools → VDO.Ninja Studio, set the stream ID, room ID, and matching password.
  3. Check OBS's streaming audio-track selection and the mixer tracks assigned to it, then start streaming. The plugin sends video and audio together. OBS Virtual Camera and virtual audio cables are unnecessary for this path.
  4. The program publisher already sends to guests in that room. Use the room's existing layout and highlight controls to arrange what guests see.

The plugin uses OBS's main Start Streaming output. It cannot also send that same output to a different streaming service at the same time. WHEP adds viewers to the active VDO.Ninja output; it does not create a second OBS streaming output.

2. Add live chat beside the video

  1. Open your Social Stream Ninja session and copy its chat dock/viewing URL.
  2. In the VDO.Ninja director's room settings, enable Embed a sidebar widget for all and paste that URL.
  3. Have a guest confirm that the chat sidebar appears and that new messages arrive.

Use the chat viewing link appropriate for guests. A page that refuses embedding needs to be opened separately. The sidebar is separate from Share a link, so chat can stay visible while a shared video changes.

3. Share an OBS WHEP link

This is useful when the program should be shared as an additional video, or when a guest wants to share a WHEP source from elsewhere.

  1. Before going live, click Enable WHEP / Copy Link in VDO.Ninja Studio. This creates a separate WHEP key and copies a URL beginning with https://whep.vdo.ninja/. If already live without WHEP enabled, stop, enable it, and start again.
  2. Start the VDO.Ninja output in OBS. The copied URL works while that output is running. Anyone with the URL can watch; the room password does not protect this separate link.
  3. In VDO.Ninja, either a guest or the director clicks Share a link and pastes it. Known WHEP URLs are detected automatically. For another endpoint, choose WHEP video. A normal webpage uses Website.
  4. If the endpoint needs a bearer token, choose WHEP video to show the token field and enter it there. That token must be shared with the viewers so their players can connect.
  5. Click Change or stop sharing to replace the link or remove it. Your own preview has no audio.
Already sharing What a new WHEP link does
Camera or main WHEP feed Adds an extra video; keeps the main feed running.
A WHEP link through Share a link Replaces that extra video.
A screen share in the extra-video slot Asks before replacing the screen share.

There is one main feed and one extra screen/WHEP feed. Ordinary website links keep their existing embedded-page behavior. To disable plugin WHEP hosting, clear WHEP link key (blank disables) in the streaming settings and restart the output.

4. Keep guest audio comfortable

A full OBS program often contains the guest's own voice. Sending it back makes them hear themselves with a delay. Choose an OBS streaming audio track that contains the audio they need and excludes their own microphone where possible. Headphones help with speaker feedback, but do not remove a delayed copy of their voice from the program.

One shared program audio track cannot provide a different mix-minus for every guest. Decide which audio belongs in that return feed before using it as the guests' main monitoring source.

If video or audio does not arrive

  • Works locally, fails on another network: the public WHEP broker exchanges connection messages; it does not relay the program itself. Configure working TURN servers in the plugin's Custom STUN/TURN Servers setting for restrictive networks. Test with a guest outside your network.
  • Video but no program audio: check the OBS streaming track and its mixer assignments. A browser may also need a click to allow audio playback.
  • WHEP URL opens as a webpage: paste it into Share a link and choose WHEP video. The endpoint must support browser CORS. Use HTTPS for a remotely hosted endpoint.
  • Too many viewers: WHEP viewers and ordinary VDO.Ninja viewers share the plugin's viewer limit and upload capacity. Each viewer receives a separate media connection.
  • Still using OBS Virtual Camera: it provides video only. The browser needs a separate audio input; on Windows, a virtual cable's recording/output device is normally the input selected in VDO.Ninja. Restart the browser after installing or changing virtual audio devices.

Other streamers can receive the program in their own OBS and choose their own broadcast destination. Avoid returning their broadcast or monitoring audio into the same shared program.
